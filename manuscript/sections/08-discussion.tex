\section{Discussion and Limitations}
\label{sec:discussion}
The evidence map supports the deployment-specific choices in Table~\ref{tab:guidance}. Fast notification delivery reduces invalidation delay but supplies no synchronous freshness guarantee.

\paragraph{Derived outputs.} Current inputs do not make a generated output current. Reusing an output for equal inputs is safe only if the input keys capture every dependency and the output asserts nothing beyond them; a draft with current structured fields can still carry stale text from context outside the keys. The task oracle (\S\ref{sec:agent-tasks}) checks structured inputs, task identity and nonempty text, not whether the text reflects the new facts.

\paragraph{External validity.} Emulators on one host, with scripted mutations, supply the source map, policy campaigns and counterexamples. Physical results come from one phone (\PhysTBD{model, Android version and build fingerprint}) and describe that device, not every vendor or release; where phone and emulators differ, we report both. Experiments the phone cannot run (\PhysTBD{list from the feasibility check}) keep emulator results only. Gap frequency comes from a 24-hour state log on that phone (\PhysTBD{usage mode and gaps per type}), not from field users, so it shows which gaps occur, not how often across users. The summed-call model and measured draft tasks have different workloads. Unsupported stock contracts remain disabled, and selected query inspection is not population coverage. Ambiguous temporal overlaps are not counted as successes.

\paragraph{Platform opportunities.} Useful APIs would return values and sequence counters atomically, expose reset-safe epochs and complete changes including deletions, and support conditional effects. Public counters alone would not repair an inconsistent observation. Such APIs could make reuse worthwhile for expensive sources, but the present measurements do not establish a general performance advantage.
