\begin{abstract}
A mobile client that remembers phone state must decide whether a cached fact still holds after a lifecycle gap. The right strategy depends on what the gap does to notifications: a background process receives callbacks late, a frozen process after thaw, and a killed, force-stopped or unregistered process never, so notification silence is insufficient evidence. This measurement study maps these behaviors for seven Android sources and background, foreground-service, system-bound assistant and persistent-system deployments on Android 13 and 15 emulators. Provider generations and row versions detect many staged changes, but a value read followed by a version read can certify the wrong value; timestamps and database resets introduce further gaps. Our evidence map therefore separates candidate stamps from established freshness certificates. A conservative client returns UNKNOWN when the complete snapshot and reset contract is unestablished; a one-row cooperative provider is a positive control. For cheap provider queries, direct refresh is faster than optimistic stamp validation, and input memoization saves model calls for derived facts. Independent trial counts, verified process states and anchoring counterexamples support deployment-specific guidance. The results come from emulator schedules, a reference provider and one physical phone (\PhysDevice); arbitrary stock-provider certification remains open.
\end{abstract}
